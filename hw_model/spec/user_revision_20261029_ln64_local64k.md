# 2026-10-29 本轮计算单元与 LN64 验证要求

本次直接用户请求为：

> 不需要乘法器是144或者128，可以试一下33*4的，或者其他的，LN 改为 64周期一行，延迟 L=64、启动间隔 II=64。按照修改后的要求验证新的方案和之前列出的所有方案

本轮只将 LN 核心固定为 L=64、II=64，最多一行核心在处理；不扫描其他 LN 时序。输入提取和输出写入继续额外计时。本行输出写入确认后才准备下一行，完整链路实际启动间隔可大于 64 周期；在八 bank 无争用时理论服务组成约为 8+64+4=76 周期。

用户本次没有修改 SRAM 容量，因此本轮沿用此前架构研究的八个 4096×16-bit 单端口宏，共 65,536 B，局部总读写峰值 16 B/周期。工作区既有的四 bank、32 KiB / LN64 是独立配置，继续保留，不能自动带入本轮并导致 FFN2 被容量拒绝。

其他条件保持：150 MHz 假设、共享权重 512 KiB、4 B/beat、每两周期接受一拍、响应延迟三周期、最多两个在途、稳态十进制 300 MB/s；W8A8、INT32 累加、残差对齐后 LN 输入 INT16、最终输出 INT8；输入激活和参数预先就绪。工作负载 M=99、N=64，投影 R=64、FFN2 R=256。主测量窗口到最后内部输出确认，不含外部激活初装及共享输出写回。

不限制物理乘法器为 128 或 144。所有此前运行的八个映射以及讨论过的其他形状均纳入本轮，并补充不同规模的高复用候选。每个阵列按 P 个 token × Q 个输出通道 × 1 个归约元素计算，需要 P×Q 个物理乘法器、4PQ B 的 INT32 累加器、2P B 的两组输入操作数寄存器、2Q B 的两组权重寄存器。阵列不引入部分和 SRAM 或本地权重 SRAM。

纳入候选：原 A(9×16)、B0、B1_G9、B1_G99、18×8、16×8、32×4、B1_G11；以及 33×4、33×8、32×8、36×4、17×4、33×2、9×8、11×8、3×16、3×32、33×16、17×8、33×32、11×4、99×4、99×8、66×4、99×16、66×8、66×16，共 28 种映射、56 个完整子图案例。

尾组、bank 冲突、包有效掩码、实际部分和生命周期、后处理回压、LN 排队和所有寄存器容量均须由有限资源仿真计入。小于 4 B 的权重包仍消耗完整的 4 B 总线拍，未实现跨包拼接时不能按有效字节假设满带宽。所有候选的物理资源单独列账，不能把增加乘法器视为免费。

原 64 KiB / LN128 的十六个结果在原条件下独立做完整字典回归；本轮 56 例使用同一 LN64 条件比较并冻结源码精确重放。旧条件结果不能混入本轮同条件排名。各个阵列分别建模，不代表已经实现一套可重构硬件。实际频率、面积、功耗和 LN 内部位精确定点运算仍待后续验证。

本轮配置：`configs/ln64_local64k.json`，场景 ID：`fixed300_local64k_ln64`；入口：`python -m hw_model.architecture_study_ln64`。
