# 2026-10-29 用户追加验证要求

本记录保存聊天中由用户直接提出的修改，优先于此前默认合同中相冲突的固定项。

用户原文：

> 不需要乘法器是144或者128，可以试一下33*4的，或者其他的，LN 改为 64周期一行，延迟 L=64、启动间隔 II=64。局部激活存储配置改为四个 16 bit×4096 单端口宏，共 32 KiB，按照修改后 的要求验证新的方案和之前列出的所以方案

本轮固定配置：

- 时钟继续假设 150 MHz，权重继续使用同一 300,000,000 B/s 接口；不扫描这些平台参数。
- 局部 SRAM 为四个 4096×16 bit 单端口宏，共 32,768 B。每 bank 每周期至多一个读或写，合计最多 8 B/cycle；读延迟继续为 1。
- LN 核心延迟 L=64、额定启动间隔 II=64，最多一行在处理。输入提取和输出写入仍单独计时并争用局部 SRAM；本行输出确认后才准备下一行，因此实际核心启动间隔可大于 64。
- 计算单元不再限定为 144 或 128 个乘法器。加入 33×4 及其他具有不同并行度的候选，所有物理乘法器、尾组、寄存器和实际访问均列账。
- 既有 W8A8、INT32 累加、残差合并后 LN 输入 INT16、最终输出 INT8、工作负载 M=99/N=64/R=64或256 保持相同。
- 默认比较维持相同驻留边界和完整张量分配，未获额外定义前不引入隐含共享溢出、分块激活装载或生命周期复用。容量不足是合法的不可行结果，不记录为 0 周期，也不把其他异常当成容量失败。
- 既有 64 KiB/LN128 结果只用于独立历史回归，不能与新条件混排后声称同条件加速。

与原默认平台分开保存的配置为 `configs/ln64_local32k.json`，场景 ID 为 `fixed300_local32k_ln64`。

本轮候选包括所有已运行的八种映射，另加 33×4、33×8、32×8、36×4、17×4、33×2、9×8、11×8、3×16、3×32、33×16、17×8 阵列。不同阵列分别建模，尚未实现可重构切换、RTL 综合、实际频率或功耗验证。
