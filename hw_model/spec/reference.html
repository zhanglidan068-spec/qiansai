KWT 硬件行为模型开发技术文档

版本 1.0　日期 2026 年 10 月 28 日

比较对象：9×16 PE 阵列与逐行 128 乘法器组及可重构加法树

1 文档目标与交付边界

在编写完整 RTL 之前，建立一个可复现的软件行为模型，比较两种架构完成同一 KWT 工作负载时的时延、存储访问、缓存需求和资源开销。比较范围必须包含矩阵计算、残差、LayerNorm（LN）、数据格式转换、数据搬运和有限缓存，不能只比较乘法次数或首行输出时间。

采用一个共用的仿真内核，接入两个计算后端和可替换的调度策略。模型首先解释性能差异来自哪里，再用于筛选硬件方案。最终标准单元面积与工作频率仍由指定库综合核验。

本文提供开发规格、接口约定、配置示例、计算基准和验收方法。文中的 Python 片段及文件结构是实现模板；除明确标注的算术基准外，不表示完整仿真器已经实现或通过 RTL 校准。

第一阶段最小可用模型只实现两个融合子图：输出投影 → 残差 → LN，以及 FFN2 → 残差 → LN。 待它们通过验证，再扩展到完整编码器和十二层。性能模型可先使用张量形状和地址，不必等待语音数据集与量化模型全部就绪。

1.1 必须回答的问题

  1. 在相同平台接口、数值格式及工作负载下，哪个方案完成全部 99 个 token 更快？
  2. 逐行方案提前启动 LN 的收益，是否会被权重供数等待抵消？
  3. 缓存缩小后，是否增加上游读取，或造成前后级阻塞？
  4. 两种方案各自至少需要哪些 SRAM 宏、寄存器和接口资源？
  5. 在未知共享 SRAM 参数的情况下，结论在什么参数范围内成立？

1.2 三种模型分开维护

模型 输入和作用 可以支持的结论
数值参考模型 浮点或量化张量，计算真实数值 逐算子误差、溢出、完整分类准确率
硬件行为模型 算子图、地址、资源和时序配置 周期数、等待原因、存储访问和缓存峰值
资源清单及综合模型 宏实例、寄存器、计算逻辑及指定库 宏面积精确汇总，标准单元面积逐步校准

NumPy 或 PyTorch 的实际运行耗时不得作为硬件时延。Python 的任意精度整数也不能代替硬件溢出规则。硬件行为模型可以使用事件驱动加速执行，但其时间语义必须与逐周期模型一致。

2 固定工作负载与待确认条件

2.1 模型基线

模型固定为 ARM keyword-transformer 仓库提交 237e4097 下的 KWT-1，使用已核验的 12 类模型配置与检查点。保持批大小 1、序列长度 99、隐藏维度 64、单注意力头、FFN 隐藏维度 256、编码器层数 12。原始参数是 FP32，INT8 等格式属于硬件方案，不能当作官方权重的原始格式。[1][2]

编码器采用 PostNorm。两处 LN 都处理一个 token 的 64 个通道；256 维位于 FFN 内部，后接 GELU，不是 LN 的输入宽度。

X ── Q K V 投影 ── QKᵀ ── 缩放和 Softmax ── AV ── 输出投影 ── 加 X ── LN1 ── H
H ── FFN1 64→256 ── GELU ── FFN2 256→64 ── 加 H ── LN2 ── 下一层输入

统一用 GEMM 记号 C[M,N] = A[M,R] × B[R,N]。R 是归约维度，避免与注意力中的 K 矩阵混淆。

算子 M N R 后续处理
Q 投影 99 64 64 无偏置
K 投影 99 64 64 无偏置
V 投影 99 64 64 无偏置
QKᵀ 99 99 64 乘 1/8，沿 99 列做 Softmax
AV 99 64 99 注意力输出投影
输出投影 99 64 64 偏置、残差、64 维 LN
FFN1 99 256 64 偏置、GELU
FFN2 99 64 256 偏置、残差、64 维 LN

每层上述矩阵运算含 6,120,576 次有效乘加，十二层合计 73,446,912 次。该计数不含非线性、残差、输入投影与分类头。报告必须声明性能边界，不能把编码器核心时间称为包含音频预处理的端到端时间。

以下赛事条件来自当前提供的赛题摘录；正式实验应把相应赛题版本与平台包版本写入实验记录。

3 公平比较规则

第一组实验在相同平台条件下比较两个具体方案：A 为 144 个乘法器的 9×16 阵列，B 为 128 个乘法器的逐行点积单元。明确数量不同，不把全部性能差异归因于数据流。

第二组实验在相同面积上限和准确率要求下分别优化两种方案。允许各自调整内部缓存、分块和数据排列，但增加的 SRAM 宏、寄存器、转换逻辑与搬运流量必须计入。可额外提供相同乘法器数量的对照实验，用来隔离结构差异，但不替代实际候选比较。

两者共用工作负载、参数值、量化规则、共享总线模型、LN 算法和启动完成边界。若要为某架构设计不同的 LN 单元，应作为另一组联合优化实验，不能与第一组混在一起。

每次实验都声明初始驻留状态：参数是否已在共享 SRAM、内部缓存是否预热、是否包含当前层装载。冷启动、层间连续执行和稳态重复推理分别报告。没有数据驻留记录的“带宽充足”结果只作为计算上限。

5 时间语义与仿真内核

5.1 周期边界

一个周期按区间 [t,t+1) 定义。周期 t 接受的延迟 L 请求，在周期 t+L 开始处完成。同步 SRAM 读取默认 L≥1，不允许请求在发起瞬间返回数据。不同频率模块使用统一整数时间单位或显式时钟比，禁止直接混用周期数。

每个周期按固定顺序执行：

  1. 应用本周期开始时到期的完成事件，更新可见数据与已释放资源。
  2. 从统一快照收集各模块意图，不在收集过程中修改共享状态。
  3. 按固定仲裁规则分配端口、计算资源、FIFO 空位和返回数据容量。
  4. 原子提交获准动作，安排未来完成事件。
  5. 检查不变量，记录状态、利用率和等待原因，推进时间。

这保证结果不依赖 Python 调用模块的先后顺序。同周期到期事件先完成，再允许消费者在该周期发起下一项操作；本周期新发起动作不能制造未定义的零周期反馈。

while not simulator.done():
    simulator.apply_completions_at(simulator.cycle)
    snapshot = simulator.snapshot()
    intents = []
    for module in simulator.modules:
        intents.extend(module.collect_intents(snapshot))
    grants = simulator.arbiter.resolve(intents, snapshot)
    simulator.commit(grants)
    simulator.check_invariants()
    simulator.record_cycle()
    simulator.cycle += 1

上述代码表达执行顺序，具体类与返回类型由实现补齐。若数据未齐，计算单元不得部分扣取一组不可恢复的操作数；可分别预取各 bank 的数据进入有界 FIFO，待完整操作数包到齐后再发起计算。

5.2 事件驱动加速

先让逐周期版本在小尺寸上通过验证，再使用最小堆跳到下一个事件。事件键可采用 (cycle, phase, sequence_id)，保留确定性的同周期仲裁。只有当中间周期没有可发起动作或状态变化时才能跳过，不能跳过本来可以利用的总线拍或 FIFO 空位。

SimPy 可作为事件队列与进程组织工具，但其同时间事件仍按确定顺序依次处理；必须自行实现硬件的请求收集和原子仲裁语义，不能依靠进程创建顺序模拟并行端口。[3]

6 存储与搬运模型

6.1 共享 SRAM 与接口

至少建模容量、数据拍宽度、请求接受间隔、返回延迟、最大未完成请求数、读写是否共用通道、突发长度、仲裁策略和其他主设备流量。峰值 B/周期 × 效率 只能用于第一轮敏感性扫描，正式模型要由请求和响应计算实际吞吐量。

容量访问检查包括地址越界、活跃张量覆盖、按需对齐和有效字节掩码。DMA、CPU 或其他主设备通过同一仲裁器申请已有资源；不能让各模块分别获得一份完整共享带宽。

定义接口层级：参数源 → 共享 SRAM、共享 SRAM → 局部缓冲、局部缓冲 → 计算寄存器、结果回写。每一级分别记录字节与事务数。既有 SRAM 面积免计不意味着访问零延迟、无竞争或免费能耗。

6.2 SRAM bank 与宏实例

每个 bank 明确宏类型、深度、16 bit 字宽、端口角色、延迟、写掩码和同地址冲突规则。单端口宏每周期最多执行一个读或写。1R1W 与真正双读写端口分别实现；宏未说明的行为按不可用处理，不能默认支持两个并行读取。

对每次请求先进行地址到 bank 的映射，再仲裁。银行数足够并不意味着任意访问都无冲突。转置、分 bank 打包、尾部补齐与 DMA 解包的吞吐和空间都要计入。

9×16 阵列的 INT8 满载映射每周期需要 9 个 A 和 16 个 B 元素。一个可行的局部布局是：

A bank p, word k = {A[2p,k], A[2p+1,k]}，p=0..4，最后一个位置填充
B bank q, word k = {B[k,2q], B[k,2q+1]}，q=0..7

五个 A bank 与八个 B bank 同时读，可提供 26 字节，其中 25 字节有效。选用最小宏时，13×256 B＝3,328 B；若用两套单端口 bank 实现完全分离的读写乒乓，则是 26 个宏、6,656 B。双端口能否以一套 bank 存放两组数据取决于宏端口和地址安排。这些是可行布局示例，不是唯一实现或已经通过面积约束的结果。

逐行方案在两个 64 维点积模式下，若一整行 A 已保存在寄存器，每周期仍需 128 个新的 B 元素。若全部从 16 bit 单读口宏直接提供，则要 64 路并行读取；也可用其他缓存和寄存器组织，但其面积与填充成本不能省略。若 AV 概率为 INT16，操作数位宽、读流量和乘法器支持方式必须另算。

6.3 有限缓冲和反压

400 bit 输入寄存器仅容纳两组 200 bit 操作数，不是完整 tile 缓存。模型必须记录填充、消费和有效位，不能每周期隐式补满。

所有缓冲的生命周期为 FREE → RESERVED → FILLING → READY → IN_USE → FREE。结果在飞行途中也占用预留容量，避免多个生产者承诺同一空间。缓冲满时前级停止发起，或进入明确的结果保持状态；保持结果占用的寄存器也应计入。

输出容量可在发起时预留，也可允许结果先留在累加器中等待排空，两种策略必须明确区分。不能因为输出 FIFO 满，就让尚未完成的计算丢失；也不能把整个九行结果原子写入容量只有一行的队列。

张量仅在最后一个消费者完成读取后释放。残差输入在加法消费完成前不能被覆盖。保留权重块遍历 token 与逐行完成全部输出是不同循环顺序，切换策略时同步更新活跃部分和数量及 LN 前缓存需求。

6.4 容量与访问量分开统计

对于输入 INT8、LN 前 INT16 的直接分组调度，以下是有效数据工作集，不是物理宏容量下限：

数据 阵列同时处理九行 逐行处理一行
输出投影输入 64 维 576 B 64 B
FFN2 输入 256 维 2,304 B 256 B
LN 前 64 维结果 1,152 B 128 B

表中不含乒乓、残差、权重、LN 内部工作区及部分和。改变分块或流式输出后，实际驻留量可能变化，应由张量生命周期统计，而非把“九倍”写成固定硬件定律。

7 两个计算后端的实现

7.1 后端 A 为 9×16 输出驻留阵列

每个 PE 含一个乘法器和累加寄存器。行广播 A，列广播 B。仅当本周期所需操作数包完整、累加依赖满足且资源可用时发起一次更新。有效乘法数等于有效行数乘有效列数；尾块无效 PE 不增加有效 MAC 计数。

典型循环为 token_group → output_channel_group → reduction_chunk → reduction_index。输出通道块完整后必须排空、转换或转存其结果，再复用累加寄存器。可替换循环顺序测试权重驻留，但不能在保持九行完成时间不变的同时，隐式获得跨全部 token 的权重复用。

偏置在每个输出第一次初始化时加入，归约分块续算不得再次添加。对称 INT8 方案下，累加位宽可先设为 INT32，但模型必须允许更改并验证溢出。乘法流水线延迟与累加反馈间隔分别配置；多周期反馈不能自动假设每周期更新同一个累加器。

在操作数无限供应、无反馈停顿、无排空和流水线开销时：

T_array_issue = ceil(M/9) × ceil(N/16) × R

该式是算术发起基准，不是完整硬件周期。输出投影需要四个通道块完成后，一行才具备全部 64 个通道；第一块 16 通道就绪不等于可以完成 LN。

7.2 后端 B 为逐行 128 乘法器和可重构加法树

默认一个 token 一次推进两个输出通道，每个通道并行处理 64 个归约元素。A 行驻留在寄存器或缓存，B 按输出列所需顺序提供。每个完整 64 维点积经过乘法及归约流水线后产生一个输出。

典型循环为 token → output_channel_pair → reduction_chunk。R=64 时每个输出对一次发起；R=256 时每个输出对四次发起并累加部分和。缓存和队列按最多两个输出的结果片段组织。

T_row_issue = M × ceil(N/2) × ceil(R/64)

这是一种确定映射。不能不加说明地把 ceil(M×N×R/128) 当成所有形状下都能达到的周期数。

对于 AV 的 R=99，可增加第二种映射：64 个输出通道各用两个乘法器与两路加法树，每周期处理两个 token 位置，50 次发起完成一行。该模式需要 64 个累加状态、输出通路及相应数据布局。若没有实现这个模式，就按原来的映射统计，不能借用优化后的周期数。

加法树的分组切换、流水寄存器、归约延迟、部分和反馈、取数选通均进入配置或资源模型。SpAtten 的可重构归约是设计参考，不能直接套用它在不同存储系统上的吞吐或能耗结果。[4]

7.3 供数约束

每个输出投影权重矩阵有 4,096 个 INT8 元素；FFN2 有 16,384 个。若没有跨行 B 缓存，逐行方案每个 token 都读取一遍。16 B/周期的 B 供数下，单行下界分别为 256 与 1,024 周期，不能继续使用 32 与 128 周期的纯计算结果。

如果 B 已驻留在更宽的内部缓存，上述限制发生在内部缓存首次填充，而非每个 token；模型用真实驻留状态决定。每次报告明确“16 B/周期”指哪一级通路，以及是否与激活、输出共用。

8 残差与 LN 融合模型

8.1 行结果的生命周期

矩阵后端产生带 token 和通道编号的片段。RowAssembler 按行维护 64 位通道有效掩码，在接收第一个片段时申请存储，并检查重复或遗漏通道。

每个通道需先完成指定的偏置、缩放、残差对齐与加法，才能成为 LN 输入。残差未返回时，即使矩阵结果已就绪，也不能把该通道计入 LN 的有效统计。

建议定义这些事件：

MAT_FRAGMENT_READY → RESIDUAL_OPERANDS_READY → LN_INPUT_FRAGMENT_READY
→ ROW_COMPLETE → LN_ACCEPT → LN_STATS_READY → LN_OUTPUT_FRAGMENT → LN_ROW_DONE

允许在 LN 输入片段陆续到达时累计统计量，但最终均值和方差必须等 64 个通道完整。输出阶段仍需原始 LN 输入或等价中间值，不能因统计已完成就提前释放数据。存储释放时刻是最后一次读取真正完成，而不是最后一个请求刚发出。

8.2 功能公式与定点边界

mu = sum(x[j], j=0..63) / 64
var = sum((x[j] - mu)^2, j=0..63) / 64
y[j] = gamma[j] × (x[j] - mu) / sqrt(var + epsilon) + beta[j]
epsilon = 1e-6，按参考模型的实数尺度定义

可采用平方和形式计算方差以便流式累计，但有限精度下它不必与两遍减均值形式完全相同，必须由数值模型验证。记录求和、平方、方差、倒平方根、gamma/beta 的格式与舍入位置。

不同输出通道若使用不同缩放尺度，不能直接对原始量化整数求均值。先对齐到公共 LN 输入尺度，或明确实现等价的带尺度统计。残差两支也必须对齐尺度。epsilon 不能直接以无单位整数 1 替代；负方差修正、零方差路径和饱和规则需明确。

8.3 两级 LN 时序模型

L0 行级模型用于初筛，配置 latency_cycles、initiation_interval_cycles 和 max_inflight_rows。同时满足资源、数据和输出容量条件时才能接收一行。延迟是接收到完成的时间，接收间隔是相邻行允许启动的最小间隔，二者不是同一参数。

L1 分阶段模型用于最终候选比较，将 LN 拆成输入与统计、均值方差、倒平方根、重读与仿射输出。配置各阶段通道吞吐、延迟、共享乘法器/查表端口、gamma/beta 读取和缓冲容量。各阶段延迟不能简单相加后又额外叠加一次行级延迟，以免重复计时。

如果均值阶段与矩阵结果输出重叠，事件表必须说明统计从哪个片段开始。若 gamma/beta 常驻寄存器，只计首次装载及寄存器面积；若存 SRAM，逐次访问仍受端口限制。

8.4 首行与整层的指标

至少记录首个矩阵片段、首行完整矩阵结果、首行完整 LN 输入、LN 接收首行、LN 首个输出及 LN 最后一行完成时刻。首行优势是否能转化为整层收益，取决于 LN 接收间隔、矩阵行产生速率和有限缓冲。

同一个矩阵引擎不能同时执行输出投影和 FFN2，也不能免费同时执行 FFN1 与 FFN2。矩阵与独立 LN 单元可以重叠，但需要资源与数据依赖实际允许。非流式 KWS 仍然允许一次样本推理内部的算子流水。

9 扩展到完整模型

第一阶段融合子图通过后，再加入 QKV、QKᵀ、Softmax、AV、FFN1 和 GELU，并保持完整依赖图。下一层 QKᵀ 对全部 K 的依赖会限制跨层逐行推进，不能把两个融合子图的首行优势直接外推为十二层都能完全流水。

Softmax 的行宽为 99，不是 64。稳定实现通常包含行最大值、指数、归约求和、归一化等阶段；各遍读取、指数临时值保留、除法吞吐和缓存都应建模。若使用在线算法或重计算减少缓存，要单独验证数值等价与工作量变化。

GELU 是逐元素算子，可与 FFN1 的结果片段衔接，但需要描述近似方法、接收间隔和输出格式。复用 LN 或 Softmax 的算术资源时，通过同一资源对象仲裁，不得同时假设各自独占全部资源。

输入投影、位置编码与分类头是否在硬件、CPU 或比较边界之外，由正式任务划分确定。端到端报告必须包含实际属于测量边界的工作，不把不同边界的数字放在同一排名中。

12 算术与调度基准

12.1 无存储限制的计算发起周期

配置为 INT8、每周期 144 或 128 次乘法、无流水线与排空开销，得到以下可手算基准。QKV 分别计算；AV 的逐行方案启用 64 组两路归约模式。

运算 9×16 阵列 逐行 128 乘法器
QKV 三个投影 8,448 9,504
QKᵀ 4,928 4,950
AV 4,356 4,950
输出投影 2,816 3,168
FFN1 11,264 12,672
FFN2 11,264 12,672
每层合计 43,076 47,916

第一行完整矩阵结果：输出投影为 256 对 32 周期，FFN2 为 1,024 对 128 周期。阵列在该时刻完成九行，逐行方案完成一行。不能据此宣称整体吞吐量相差八倍。

12.2 行级 LN 的人工检查样例

仅为调度单元测试，设 LN 延迟与接收间隔均为 64 周期，单行执行，输入缓存无限，无残差与结果搬运开销。阵列每批九行同时就绪，逐行单元依次产生行。

对第 i 行，矩阵就绪时刻为 a[i]，LN 完成时刻为 f[i]：

f[-1] = 0
f[i] = max(a[i], f[i-1]) + 64
子图 架构 全部 99 行完成 LN
输出投影加 LN 阵列 6,592 周期
输出投影加 LN 逐行 6,368 周期
FFN2 加 LN 阵列 11,840 周期
FFN2 加 LN 逐行 12,736 周期

这个基准用于检验调度器，不用于最终架构排名。有限缓存、端口冲突、部分和排空、残差和实际 LN 流水线必须在详细模型中重新计算。L0 的无限缓存模式必须显式命名并禁止混入正式结果。

12.3 边界与资源测试

必须覆盖：M 为 1、8、9、10、99；N 为 1、15、16、17、64、99、256；R 为 1、31、32、33、64、99、256。关注最后一块掩码、INT8 奇数元素打包、跨地址边界、归约续算只加一次偏置。

资源测试包括：单端口同周期读写拒绝、两请求映射同 bank、输出缓冲仅一行、LN 停顿、残差晚到、DMA 未完成数受限、读写共享总线、双缓冲切换和最后一块排空。测试要验证独立的计算结果和资源约束，不只是重复实现中的公式。

13 数值验证与 RTL 对接

数值验证先建立浮点基线，再按赛事规定从训练划分取样标定；验证划分用于功能调试和准确率验证。标定用于确定量化尺度等参数，不等于在验证集上重新训练。

使用高精度参考计算检查小矩阵，再显式模拟定点缩放、舍入、截断、溢出和非线性近似。整数累加在足够宽且中间不舍入的情况下可以改变求和顺序；若树内逐级截断或使用浮点，顺序变化可能影响结果。

性能模型的事件与数值模型通过 tensor_id、token、channel 和 tile_id 对齐。小尺寸联调可携带真实数据；大规模扫描可只携带元数据。数据相关分支或稀疏优化必须由真实数据或明确工作负载轨迹驱动，不能凭空给予跳过收益。

候选收敛后，只为关键差异模块实现小规模 RTL：计算后端、bank 与接口控制、LN 输入输出与行缓存。向软件与 RTL 注入相同的请求、数据和背压轨迹，比较接受事件、输出值、输出时刻和逐级读写次数。

若软件尚未精确建模某个流水线阶段，可先允许已解释的固定延迟偏差，再逐项收敛；不得用一个任意修正系数掩盖带宽、缓冲或调度错误。

14 面积与能耗处理

新增面积计算为：

A_new = A_standard_cells + sum(instance_count[type] × macro_area[type])

标准单元包括计算、寄存器、接口、FIFO 控制、地址生成、重排和转换逻辑。新增 SRAM 宏按实际实例统计，不因映射到共享地址空间而免计。既有 E203、共享 SRAM 与固定总线外设单列。

宏类型与数量确定、官方面积已导入时，可准确汇总该部分。宏面积未知时输出 unknown，不能设为零。综合报告如果已包含宏黑盒面积，需要明确剔除或避免二次计入。把多余有效存储映射到宏后，按整个宏面积计费。

早期可用小模块综合得到乘法器、累加器、加法树和控制的估计区间，但不能仅按乘法器数量线性推导整个加速器面积。两种架构的工作频率可能不同，应同时报告等频周期比较和综合可达频率下的时间比较。

能耗只有在具备对应工艺、宏和位宽的操作能耗或活动率数据时才汇总；否则报告访问量和活动次数，不把“读命令少”直接等同于“功耗更低”。

15 实验顺序与停止条件

阶段 实现内容 进入下一阶段的条件
A 算子尺寸与两个纯计算映射 第 12 节周期和有效 MAC 全部匹配
B 行级残差 LN 调度 首行和末行基准匹配，事件顺序确定
C 有限缓存和真实 bank 请求 无越界、覆盖、端口超用或数据丢失
D 共享接口与 DMA 请求响应可追踪，带宽账本闭合
E LN 分阶段与数值模型 位宽、读写和数值结果均可解释
F 完整编码器及十二层 全依赖图、层间搬运、参数装载纳入
G 小 RTL 校准与方案筛选 关键时序及面积有综合或仿真依据

先做小范围单变量扫描，再围绕排名变化的区域联合优化，不必一开始跑全组合。带宽扫描可用 4、8、16、32、64、128 B/周期等假设值，但必须注明属于哪一级通路，不能把不可实现的值标为平台能力。

LN 扫描分别改变通道并行度、接收间隔与阶段延迟；缓存扫描以真实宏组合为单位，同时记录有效容量和物理容量。400 bit 寄存器方案可作为一个输入级候选，不自动代替整个权重和激活缓存。

当一种方案在准确率、实际可实现面积与目标性能下被另一种方案全面超过，可以停止继续优化它。若结果依赖尚未确认的总线或宏参数，保留条件性结论，优先获取能够改变选型的那一个平台参数。

16 完成检查表

  • 两种后端处理同样的 99 个 token，输出元素总数正确，尾块不重复或遗漏。
  • 两处 LN 均为 64 维，Softmax 为 99 维，FFN 中间 256 维不混用。
  • 每个计算事件都能追溯到已就绪的操作数；没有免费转置、免费缓存填充或无限返回队列。
  • 总线拍和宏端口没有超额分配；数据流中每次物理传输有唯一计费位置。
  • 行缓存、权重、残差和部分和都计入驻留空间；在飞行输出已预留容量。
  • 缓存不足可以造成停顿，但不改变正确结果；死锁时输出等待链和持有资源。
  • LN 延迟、接收间隔与缓存占用独立描述；首行与整层时间分别输出。
  • 原始数值误差与硬件性能指标分开；没有用 Python 执行耗时作为硬件性能。
  • SRAM 面积使用官方实例数据；未知标准单元面积未被伪装成已通过面积约束。
  • 结果带配置、来源和初始状态，可重复运行；L0 假设结果与 L1 详细结果有清晰标识。
